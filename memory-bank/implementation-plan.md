## 2. 实施目标

### 2.1 第一阶段总目标

交付一个可在 Windows 上稳定构建和运行的单人动作迷宫游戏 MVP，满足以下产品特征：

- 单人闯关主流程可玩
- 12 个主线关卡中的前 4 关可完整体验
- 奖励关系统有 1 个可运行版本
- 基础分数、敌人、核心成长道具、隐藏出口、重开循环完整可用
- 生成便携版 Windows 构建包

### 2.2 第一阶段完成标准

- 能在开发机和 CI 上稳定输出 Windows Release 包
- 玩家可以从主菜单进入游戏、完成关卡、失败重开、进入奖励关
- 地图、敌人、核心成长道具、倒计时和出口逻辑都由数据驱动
- 没有阻塞通关的严重 bug
- 规则反馈足够清晰，玩家不会因为判定不明而频繁误死

## 3. 技术路线与工程骨架

### 3.1 技术选型

- 引擎框架：`Bevy`
- Tile 地图：`bevy_ecs_tilemap`
- 关卡制作：第一版直接使用 `LDtk`
- 音频：Bevy 原生音频系统
- UI：Bevy 原生 UI
- 构建：`cargo build --release`
- Windows 目标：`x86_64-pc-windows-msvc`

### 3.2 推荐工程结构

建议项目至少拆分为以下模块：

- `app`
  - 应用入口、插件注册、状态机初始化
- `core`
  - 游戏状态、通用组件、时间与配置
- `map`
  - tile 数据、关卡加载、软墙生成、出口埋点
- `player`
  - 输入、移动、炸弹放置、角色状态
- `bomb`
  - 炸弹生命周期、引信、连锁爆炸、火焰传播
- `enemy`
  - 敌人组件、行为系统、追踪逻辑、超时惩罚敌人
- `pickup`
  - 成长道具、战术道具、拾取与掉落
- `ui`
  - 主菜单、暂停、HUD、失败、通关、奖励关提示
- `audio`
  - 音效事件、BGM 状态切换
- `progression`
  - 分数、生命、战役推进、奖励关插入

### 3.3 数据驱动原则

以下内容必须走外部数据文件，不得硬编码在系统逻辑中：

- `LDtk`：主线与奖励关的地图格子、出生点、出口点、敌人标记、道具标记
- 侧边配置：倒计时、敌人编排结果、核心成长道具分配、主题区配置、分数规则、UI 文案和教学提示
- 同一关卡在设计阶段完成编排后必须固定到数据中；同关重开不得重新随机

### 3.4 运行时规则前提

- 玩家与敌人的逻辑移动都按格进行，视觉表现允许平滑插值
- 玩家与敌人仅在到达格中心时选择新方向
- 玩家死亡并消耗生命后，当前关卡重置到初始状态；保留生命、分数和核心成长，丢失战术道具
- 所有主线关卡使用 `300` 秒倒计时，并在 HUD 上持续显示
- 倒计时归零后，地图上新增 `2` 个 `Punisher`；生成位置随机，但必须与玩家当前位置保持最小安全间隔

## 4. 分阶段实施计划

### 阶段 A：项目初始化与 Windows Build 打通

目标：

- 建立可运行的 Rust + Bevy 项目骨架
- 本地 Windows 构建成功
- GitHub Actions 的 Windows 构建链打通

任务：

- 初始化 Cargo 项目与依赖
- 配置基础 Bevy app、窗口、状态机、日志
- 引入 tilemap、`LDtk` 关卡加载、侧边配置文件结构和资源目录结构
- 建立 Windows CI 工作流
- 生成第一个空白运行包并验证启动

完成标准：

- `cargo run` 能打开窗口
- `cargo build --release` 能生成 Windows 二进制
- CI 能产出可下载 artifact

### 阶段 B：核心玩法闭环

目标：

- 做通 “移动 -> 放弹 -> 爆炸 -> 炸墙 -> 清怪 -> 出口显现 -> 过关”

任务：

- 实现 tile-based 地图和碰撞
- 实现玩家移动、死亡、重开
- 实现炸弹引信、十字爆炸、连锁反应
- 实现硬墙阻挡、软墙摧毁、炸弹实体阻挡
- 实现隐藏出口与显现逻辑
- 实现基础 HUD，包括敌人数、生命数、核心成长状态和倒计时

完成标准：

- 玩家可在单关中完整通关
- 爆炸传播和判定稳定一致
- 自炸、自困、卡位等经典风险都能正确发生

### 阶段 C：敌人系统与关卡节奏

目标：

- 引入敌人梯度，让关卡真正具备策略压力

任务：

- 实现 `Drifter`
- 实现 `Seeker-Y`
- 实现 `Seeker-X`
- 实现 `Hunter`
- 实现 `Phantom`
- 实现超时惩罚敌人 `Punisher`
- 为每类敌人配置固定速度与碰撞反馈：
  - `Drifter 2.0 tiles/sec`
  - `Seeker-Y 3.0 tiles/sec`
  - `Seeker-X 3.0 tiles/sec`
  - `Hunter 4.0 tiles/sec`
  - `Phantom 2.0 tiles/sec`
  - `Punisher 4.0 tiles/sec`
- 将敌人转向决策统一锁定在格中心
- 将 `Seeker-Y / Seeker-X` 锁定为仅在同列 / 同行时追踪
- 将 `Phantom / Punisher` 锁定为仅可穿过软墙

完成标准：

- 前 4 个主线关卡拥有可区分的敌人节奏
- 玩家能明显感受到不同敌人带来的空间压力差异

### 阶段 D：道具与战役进程

目标：

- 让成长、分数和战役推进成立

任务：

- 实现核心成长道具：
  - `Bomb Up`
  - `Fire Up`
  - `Skate`
- 实现生命系统、主题区推进、奖励关插入
- 实现分数系统与成长道具封顶后的 `10000` 分替代奖励
- 固定前 `4` 个主线关与首个奖励关的核心成长投放与敌人编排

完成标准：

- 玩家在 4 个主线关中能获得明确成长
- 奖励关可正常进入与结算
- 分数不会阻塞主流程

### 阶段 E：内容扩展与手感打磨

目标：

- 从“功能可玩”推进到“体验稳定”

任务：

- 制作 12 个主线关与 3 个奖励关
- 接入战术道具：
  - `Remote Trigger`
  - `Soft Pass`
  - `Bomb Pass`
  - `Flame Guard`
- 接入秘密目标系统
- 优化炸弹闪烁节奏、火焰时长、受击反馈
- 优化 HUD、暂停菜单、失败/通关切换
- 补齐音效与最小可用 BGM
- 调整数值：敌人速度、软墙密度、掉落节奏、奖励关得分效率

完成标准：

- 完整战役可从头玩到尾
- 前 30 分钟体验没有明显节奏塌陷
- 玩家不会因为视觉反馈不清而频繁误判

### 阶段 F：Windows 发布准备

目标：

- 形成可以分发的首版 Windows 包

任务：

- 整理资源目录
- 生成版本号和变更说明
- 验证无开发路径依赖
- 输出 zip 包结构：
  - `BlastMaze.exe`
  - `assets/`
  - `README` 或运行说明
- 进行最终 smoke test

完成标准：

- 新机器解压后可直接运行
- 游戏资源加载正常
- 开场、进关、奖励关、失败、通关全流程无阻塞

## 6. 测试计划

### 6.1 自动化测试

优先补以下测试：

- 炸弹传播是否正确停止于硬墙与软墙
- 连锁爆炸是否按预期触发
- 出生区是否永不被软墙堵死
- 隐藏出口是否在清怪后显现
- 道具上限是否正确生效
- 同一关卡重开后敌人编排和核心成长投放是否保持一致
- 死亡重开后是否保留生命、分数、核心成长并移除战术道具
- `Seeker-Y / Seeker-X` 是否仅在同列 / 同行时追踪
- `Phantom / Punisher` 是否仅可穿过软墙
- 主线关卡 `300` 秒倒计时是否正确显示与递减
- 关卡超时后是否正确新增 `2` 个 `Punisher`

### 6.2 手工验证

每个迭代至少执行以下手工测试：

- 开场进入主菜单
- 开始第一关
- 放置炸弹并安全撤离
- 被自己炸死
- 炸死敌人
- 清光敌人并找到出口
- 奖励关进入与结算
- 战役中途死亡并重开
- 最终通关与返回标题

### 6.3 Windows 专项验证

- 干净 Windows 环境解压即运行
- 分辨率和窗口焦点正常
- 音频设备切换不导致崩溃
- 键盘输入在英文输入法和中文输入法下都正常
- Release 包无缺失资源

## 8. 风险与应对

### 风险 1：Bevy API 演进带来迁移成本

应对：

- 锁定主版本
- 在早期建立自己的薄封装层，减少全局耦合

### 风险 2：tile 规则与视觉表现不一致

应对：

- 所有判定以 tile 逻辑为准
- 渲染插值必须从属于逻辑层

### 风险 3：战术道具导致规则复杂度上升

应对：

- 先做核心成长道具
- 战术道具按优先级逐个接入
- 任何道具上线前都要通过“是否破坏经典可读性”检查

### 风险 4：Windows 发布后路径/资源问题

应对：

- 从阶段 A 起就使用发布目录结构验证
- 每次里程碑都做 Windows 解压运行测试

## 9. 验收标准

项目达到 MVP 验收时，必须同时满足：

- Windows Release 包可直接运行
- 玩家能完整玩通至少 4 个主线关和 1 个奖励关
- 规则闭环稳定：炸弹、爆炸、敌人、出口、核心成长道具、重开都可正常工作
- 体验闭环成立：失败清晰、成长明确、通关目标可理解
- 构建与运行流程对新开发者可复现
